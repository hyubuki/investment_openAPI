# 사용자 업무 모듈

상태: `Draft v0.1`

상세 계약: [사용자 API Spec](../api/사용자-API.md)

## 1. 책임과 경계

사용자 모듈은 두 개의 하위 업무를 구분한다.

- Identity & Access: 로그인 주체, Session, API Client, Credential 및 권한
- Customer: 증권 서비스를 이용하는 개인·법인 고객의 신원과 고객 상태

`User`와 `Customer`는 동일인이더라도 같은 JPA Entity가 아니다. 한 고객이 여러 사용자 또는 API Client에 권한을 위임할 수 있고, 기관 고객은 다수의 운용자와 시스템 계정을 가질 수 있다.

KYC/AML 상세 업무가 커지면 별도 업무 모듈로 분리한다.

## 2. JPA Entity

### User Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `userId` | UUID | 사용자 식별자 |
| `email` | String | 정규화된 로그인 이메일 |
| `passwordHash` | String | 단방향 Hash. API 응답 및 로그 노출 금지 |
| `role` | UserRole | `USER`, `ADMIN` 플랫폼 Role. 운영자 Role은 업무와 권한 정책이 정의될 때 추가 |
| `status` | UserStatus | `PENDING`, `ACTIVE`, `LOCKED`, `DISABLED` |
| `failedLoginCount` | int | 연속 인증 실패 횟수 |
| `lockedUntil` | Instant? | 잠금 해제 예정 시각 |
| `lastLoginAt` | Instant? | 마지막 로그인 시각 |
| `createdAt` | Instant | 생성 시각 |
| `updatedAt` | Instant | 변경 시각 |
| `version` | long | 낙관적 잠금 버전 |

불변식:

- 이메일은 trim 및 소문자 정규화 후 유일해야 한다.
- Password 원문은 저장하거나 로그에 기록하지 않는다.
- 비활성 사용자는 Access Token과 Refresh Token을 사용할 수 없다.
- Client가 가입 요청에서 Role을 직접 선택할 수 없다.

### Customer Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `customerId` | UUID | 고객 식별자 |
| `customerType` | CustomerType | `INDIVIDUAL`, `CORPORATE` |
| `displayName` | String | 표시 이름 또는 법인명 |
| `residencyCountry` | String | ISO 3166-1 alpha-2 거주·설립 국가 코드 |
| `kycStatus` | KycStatus | `NOT_STARTED`, `PENDING`, `VERIFIED`, `REJECTED`, `EXPIRED` |
| `customerStatus` | CustomerStatus | `ACTIVE`, `SUSPENDED`, `CLOSED` |
| `verifiedAt` | Instant? | 고객 확인 완료 시각 |
| `version` | long | 동시 변경 제어 |

민감한 실명확인 정보와 주민·법인 식별정보는 별도 암호화 저장소 및 접근 감사 정책을 적용한다. External API에는 최소한의 식별 정보만 노출한다.

### CustomerUser Entity

고객과 사용자의 권한 관계를 표현한다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `customerUserId` | UUID | 관계 식별자 |
| `customerId` | UUID | 대상 고객 |
| `userId` | UUID | 권한을 받은 사용자 |
| `relationshipRole` | RelationshipRole | `OWNER`, `TRADER`, `VIEWER`, `ADMINISTRATOR` |
| `status` | RelationshipStatus | `ACTIVE`, `REVOKED` |
| `validFrom`, `validUntil` | Instant, Instant? | 권한 유효 기간 |

### ApiClient Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `apiClientId` | UUID | API 애플리케이션 식별자 |
| `customerId` | UUID | 소유 고객 |
| `name` | String | Client 애플리케이션 이름 |
| `clientType` | ApiClientType | `CONFIDENTIAL`, `PUBLIC` |
| `status` | ApiClientStatus | `ACTIVE`, `SUSPENDED`, `REVOKED` |
| `createdAt`, `revokedAt` | Instant, Instant? | Lifecycle 시각 |
| `version` | long | 동시 변경 제어 |

### ApiClientScope Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `apiClientScopeId` | UUID | Scope 관계 식별자 |
| `apiClientId` | UUID | 대상 API Client |
| `scope` | String | `orders:write`, `orders:read`, `market:read` 등 |

### ApiClientAccount Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `apiClientAccountId` | UUID | 계좌 권한 관계 식별자 |
| `apiClientId` | UUID | 대상 API Client |
| `accountId` | UUID | 접근 가능한 계좌 |
| `permission` | AccountApiPermission | `READ`, `TRADE` |

### ApiCredential Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `credentialId` | UUID | Credential 식별자 |
| `apiClientId` | UUID | 소유 API Client |
| `keyPrefix` | String | 운영자가 식별할 수 있는 공개 Prefix |
| `secretHash` | String | Secret Hash. 원문 재조회 금지 |
| `status` | CredentialStatus | `ACTIVE`, `EXPIRED`, `REVOKED` |
| `expiresAt` | Instant | 만료 시각 |
| `lastUsedAt` | Instant? | 마지막 사용 시각 |

### Session

Session은 Redis에 저장하는 인증 데이터이며 JPA Entity로 만들지 않는다. Redis에는 Refresh Token 원문이 아니라 Hash와 Session 상태만 저장한다. Redis 장애 시 보안 검증을 생략하는 fail-open을 허용하지 않는다.

### 테이블 및 제약조건

| 테이블 | 주요 제약조건과 인덱스 |
|---|---|
| `users` | `email` unique, `status`, `created_at` index, `@Version` 컬럼 |
| `customers` | 고객 상태와 KYC 상태 index, 민감정보 암호화 |
| `customer_users` | `(customer_id, user_id)` unique, 유효기간 index |
| `api_clients` | `customer_id`, `status` index |
| `api_client_scopes` | `(api_client_id, scope)` unique |
| `api_client_accounts` | `(api_client_id, account_id)` unique |
| `api_credentials` | `key_prefix` unique, `(api_client_id, status)` index |

Password와 Secret의 유일성 검증은 사전 조회만 신뢰하지 않고 데이터베이스 Unique Constraint를 최종 기준으로 한다.

## 3. Service 설계

| Service | 트랜잭션 | 책임 |
|---|---|---|
| `UserService` | 쓰기 `@Transactional` | 가입, 이메일 정규화, 상태 변경 |
| `AuthService` | DB 조회 + Redis Session 처리 | 로그인, Token 회전, 로그아웃, Session 재사용 탐지 |
| `CustomerService` | 쓰기 `@Transactional` | 고객 정보와 KYC 상태 관리 |
| `CustomerAccessService` | 읽기 `@Transactional(readOnly = true)` | 사용자·API Client의 고객 및 계좌 접근 권한 확인 |
| `ApiClientService` | 쓰기 `@Transactional` | API Client, Scope 및 Credential Lifecycle 관리 |

모든 Service는 생성자 주입을 사용한다. 인증 성공 후 Redis Session 저장에 실패하면 Token을 정상 응답하지 않으며, 비활성 사용자 검사는 로그인과 매 요청 인증에서 모두 수행한다.

## 4. Repository 설계

| Repository | 주요 메서드 |
|---|---|
| `UserRepository extends JpaRepository<User, UUID>` | `findByEmail`, `existsByEmail`, `findByIdAndStatus` |
| `CustomerRepository extends JpaRepository<Customer, UUID>` | `findByIdAndCustomerStatus` |
| `CustomerUserRepository` | `existsByCustomerIdAndUserIdAndStatus`, 유효 권한 조회 |
| `ApiClientRepository` | 고객별 Client 목록, 활성 Client 조회 |
| `ApiClientScopeRepository` | Client별 Scope 조회와 교체 |
| `ApiClientAccountRepository` | Client의 계좌별 조회·주문 권한 확인 |
| `ApiCredentialRepository` | Prefix 조회, 활성 Credential 조회, 폐기 처리 |

Repository는 JPA Entity를 반환하며 Controller가 Repository를 직접 호출하지 않는다. 외부 응답은 Service에서 DTO로 변환한다.

## 5. External API 초안

| Method | Path | 성공 응답 | 인증/권한 |
|---|---|---:|---|
| POST | `/api/v1/users` | 201 | 공개 가입 정책 적용 |
| POST | `/api/v1/auth/login` | 200 | 공개, Credential 검증 |
| POST | `/api/v1/auth/refresh` | 200 | 유효한 Refresh Token |
| POST | `/api/v1/auth/logout` | 204 | 인증 필요 |
| GET | `/api/v1/users/me` | 200 | 인증 필요 |
| GET/POST | `/api/v1/api-clients` | 200/201 | 고객 관리자 |
| GET/PATCH | `/api/v1/api-clients/{apiClientId}` | 200 | Client 소유 고객 관리자 |
| POST | `/api/v1/api-clients/{apiClientId}/credentials` | 201 | Client 소유 고객 관리자 |
| DELETE | `/api/v1/api-clients/{apiClientId}/credentials/{credentialId}` | 204 | Client 소유 고객 관리자 |

### 회원 등록

```http
POST /api/v1/users
```

```json
{
  "email": "trader@example.com",
  "password": "client-secret-password"
}
```

```http
HTTP/1.1 201 Created
```

```json
{
  "userId": "018f8f3a-6bc1-7bc2-a7ef-8cd43c875111",
  "email": "trader@example.com",
  "role": "USER",
  "status": "ACTIVE",
  "createdAt": "2026-09-11T01:00:00Z"
}
```

### 로그인

```http
POST /api/v1/auth/login
```

```json
{
  "email": "trader@example.com",
  "password": "client-secret-password"
}
```

```json
{
  "tokenType": "Bearer",
  "accessToken": "...",
  "expiresIn": 1800,
  "refreshToken": "...",
  "refreshExpiresIn": 86400
}
```

### Token 갱신 및 로그아웃

```text
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
```

Refresh Token은 회전시키며 이전 Token 재사용이 탐지되면 관련 Session Family를 폐기한다.

### 내 사용자 조회

```http
GET /api/v1/users/me
```

### API Client 관리

```text
GET    /api/v1/api-clients
POST   /api/v1/api-clients
GET    /api/v1/api-clients/{apiClientId}
PATCH  /api/v1/api-clients/{apiClientId}
POST   /api/v1/api-clients/{apiClientId}/credentials
DELETE /api/v1/api-clients/{apiClientId}/credentials/{credentialId}
```

Credential Secret은 생성 응답에서 한 번만 반환하고 이후 재조회할 수 없게 한다.

## 6. 주요 오류 코드

| 코드 | HTTP | 설명 |
|---|---:|---|
| `EMAIL_ALREADY_EXISTS` | 409 | 이미 등록된 이메일 |
| `INVALID_CREDENTIALS` | 401 | 사용자 존재 여부를 노출하지 않는 통합 인증 실패 |
| `USER_INACTIVE` | 401 | 사용할 수 없는 사용자 |
| `SESSION_INVALID` | 401 | 만료·폐기되었거나 존재하지 않는 Session |
| `REFRESH_TOKEN_REUSED` | 401 | 이미 회전된 Refresh Token 재사용 |
| `SCOPE_NOT_GRANTED` | 403 | API Client Scope 부족 |
| `CUSTOMER_ACCESS_DENIED` | 403 | 고객 관계 또는 위임 권한 부족 |

## 7. 내부 메시지

```text
UserRegistered
UserDisabled
CustomerVerified
CustomerSuspended
ApiClientCreated
ApiCredentialRevoked
SessionRevoked
```

인증 이벤트에는 Password, Token, Secret 원문을 포함하지 않는다.

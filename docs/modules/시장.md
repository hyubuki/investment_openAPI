# 시장 업무 모듈

상태: `Draft v0.2 (B2C)`

상세 계약: [시장 API Spec](../api/시장-API.md)

## 1. 책임과 경계

시장 모듈은 거래 가능한 상품의 기준정보, 거래소, 거래일, 시장 세션, 가격 단위 및 실시간 시장 데이터를 제공한다.

상품 기준정보와 거래 캘린더는 PostgreSQL/JPA로 관리할 Reference Data다. Quote, Order Book 및 Trade Tick은 대량 스트리밍 데이터이므로 JPA Entity로 저장하지 않고 Redis, 메모리 Snapshot 또는 별도 시계열 저장소를 사용한다. 트래픽과 배포 요구가 커지면 기준정보와 실시간 시세를 별도 모듈로 분리할 수 있다.

## 2. JPA Entity와 시세 모델

### Instrument Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `instrumentId` | UUID | 내부 상품 식별자 |
| `symbol` | String | 시장 내 상품 코드 |
| `isin` | String? | 국제 증권 식별번호 |
| `name` | String | 상품명 |
| `market` | String | 상장·거래 시장 코드 |
| `assetClass` | AssetClass | `EQUITY`, `ETF`, `BOND` 등 |
| `currency` | String | ISO 4217 거래 통화 코드 |
| `quantityScale` | int | 수량 소수 자릿수 |
| `priceScale` | int | 가격 소수 자릿수 |
| `lotSize` | BigDecimal | 거래 단위 |
| `status` | InstrumentStatus | `ACTIVE`, `HALTED`, `SUSPENDED`, `DELISTED` |
| `listedAt`, `delistedAt` | LocalDate? | 상장 Lifecycle |
| `version` | long | 기준정보 버전 |

### TickSizeRule Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `tickSizeRuleId` | UUID | 규칙 식별자 |
| `market`, `instrumentGroup` | String, String | 적용 대상 |
| `priceFrom`, `priceTo` | BigDecimal, BigDecimal? | 가격 구간 |
| `tickSize` | BigDecimal | 최소 가격 단위 |
| `effectiveFrom`, `effectiveTo` | Instant, Instant? | 규칙 유효 기간 |

### Exchange Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `exchangeId` | UUID | 거래소 식별자 |
| `marketCode` | String | 외부 계약에서 사용하는 시장 코드 |
| `name` | String | 거래소 이름 |
| `timezone` | String | IANA Time Zone ID |
| `status` | ExchangeStatus | `ACTIVE`, `INACTIVE` |

### TradingCalendar Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `tradingCalendarId` | UUID | 거래일 식별자 |
| `market`, `tradingDate` | String, LocalDate | 시장과 거래일 |
| `businessDay` | boolean | 거래일 여부 |
| `holidayName` | String? | 휴장 사유 |

### TradingSession Entity

| 필드 | 타입 | 설명 |
|---|---|---|
| `sessionId` | UUID | 세션 식별자 |
| `tradingCalendarId` | UUID | 거래일 FK |
| `sessionType` | TradingSessionType | `PRE_OPEN`, `REGULAR`, `AFTER_HOURS`, `CLOSED` |
| `state` | TradingSessionState | `SCHEDULED`, `OPEN`, `HALTED`, `CLOSED` |
| `opensAt`, `closesAt` | Instant, Instant | 거래소 기준 시각 |
| `allowedOrderTypes` | JSONB/String Collection | 세션별 허용 주문 유형 |

### QuoteSnapshot Read Model

| 필드 | 설명 |
|---|---|
| `instrumentId` | 상품 식별자 |
| `lastPrice` | 최근 체결가 |
| `bestBidPrice`, `bestBidQuantity` | 최우선 매수 호가 |
| `bestAskPrice`, `bestAskQuantity` | 최우선 매도 호가 |
| `openPrice`, `highPrice`, `lowPrice` | 당일 가격 |
| `volume`, `turnover` | 누적 거래량과 거래대금 |
| `marketState` | 상품 또는 시장 상태 |
| `exchangeSequence` | 거래소 시장 데이터 순번 |
| `exchangeTimestamp`, `receivedAt` | 거래소 시각과 내부 수신 시각 |

### OrderBookSnapshot Read Model

매수·매도 가격 단계별 가격과 잔량을 보유한다. Snapshot의 sequence가 증분 데이터의 기준이 되어야 하며 gap 발생 시 Snapshot으로 재동기화한다.

### TradeTick Read Model

거래소에서 발생한 시장 전체 개별 체결이다. 특정 사용자 주문의 체결인 `Execution`과 구분한다.

### 저장소 기준

| 데이터 | 저장 방식 | 이유 |
|---|---|---|
| Instrument, Exchange | PostgreSQL/JPA | 기준정보, 이력 및 참조 정합성 |
| TradingCalendar, TradingSession, TickSizeRule | PostgreSQL/JPA | 유효기간과 시장 규칙 관리 |
| QuoteSnapshot | Redis 또는 메모리 Cache | 최신 값 중심의 고빈도 갱신 |
| OrderBookSnapshot | 전용 메모리 Store/Redis 검토 | sequence 기반 빠른 Snapshot |
| TradeTick | 스트리밍 Broker 및 필요 시 시계열 저장소 | 대량 Append-only 데이터 |

### 테이블 및 제약조건

| 테이블 | 주요 제약조건과 인덱스 |
|---|---|
| `exchanges` | `market_code` unique |
| `instruments` | `(market_code, symbol)` unique, `isin` unique where not null, 상태 index |
| `tick_size_rules` | 적용 대상·가격 구간·유효기간 복합 index |
| `trading_calendars` | `(market_code, trading_date)` unique |
| `trading_sessions` | `(market_code, trading_date, session_type)` unique |

## 3. Service 설계

| Service | 트랜잭션 | 책임 |
|---|---|---|
| `InstrumentQueryService` | `@Transactional(readOnly = true)` | 상품 검색, 상세 및 거래 가능 상태 조회 |
| `MarketRuleService` | `@Transactional(readOnly = true)` | 호가 단위, 수량 단위와 가격제한 검증 |
| `TradingSessionService` | 조회 `readOnly`, 상태 갱신 `@Transactional` | 거래일·세션 상태와 주문 허용 여부 제공 |
| `MarketDataQueryService` | Cache/Stream 조회 | 최신 Quote와 Order Book Snapshot 조회 및 최신성 검증 |
| `MarketDataSubscriptionService` | 비트랜잭션 | WebSocket 구독, sequence gap 및 Snapshot 재동기화 처리 |

시세 최신성 검사는 `receivedAt`만 보지 않고 거래소 sequence, 시장 상태와 허용 지연 기준을 함께 사용한다.

## 4. Repository 설계

| Repository | 주요 메서드 |
|---|---|
| `InstrumentRepository` | 시장·Symbol 조회, ISIN 조회, 상태별 검색 |
| `ExchangeRepository` | Market Code 조회 |
| `TickSizeRuleRepository` | 상품군·가격·유효시각에 적용되는 Rule 조회 |
| `TradingCalendarRepository` | 시장·거래일 조회, 기간별 영업일 조회 |
| `TradingSessionRepository` | 현재 세션과 주문 유형별 허용 상태 조회 |

Quote와 Order Book 접근 인터페이스는 Spring Data JPA Repository가 아닌 `QuoteStore`, `OrderBookStore`로 분리한다.

### 상품 검색과 상세

```text
GET /api/v1/instruments?market=KRX&query=005930&status=ACTIVE&cursor={cursor}&limit=100
GET /api/v1/instruments/{instrumentId}
```

### 시장 상태 및 거래 캘린더

```text
GET /api/v1/markets
GET /api/v1/markets/{market}/status
GET /api/v1/markets/{market}/calendar?from=2026-09-01&to=2026-09-30
```

## 6. WebSocket API

### 연결

```text
WSS /api/v1/stream/market-data
```

### 구독 요청

```json
{
  "type": "SUBSCRIBE",
  "requestId": "sub-market-001",
  "channels": [
    {
      "name": "quotes",
      "instrumentIds": ["018f8f3a-7c11-73b2-b411-8e71ca121111"]
    },
    {
      "name": "order-books",
      "depth": 10,
      "instrumentIds": ["018f8f3a-7c11-73b2-b411-8e71ca121111"]
    }
  ]
}
```

시장 데이터 이벤트는 상품별 sequence를 포함한다. 중간 Quote를 최신 값으로 합치는 conflation은 계약에 명시한 채널에만 허용한다. Order Book 증분 이벤트에서 sequence gap이 발생하면 Client는 해당 상품의 Snapshot을 다시 받아야 한다.

## 7. 주요 오류 코드

| 코드 | HTTP | 설명 |
|---|---:|---|
| `INSTRUMENT_NOT_FOUND` | 404 | 상품을 찾지 못함 |
| `INSTRUMENT_NOT_TRADABLE` | 422 | 거래 정지·상장 폐지 등으로 주문 불가 |
| `MARKET_DATA_NOT_AVAILABLE` | 503 | 시세가 없거나 최신성 기준을 충족하지 못함 |
| `INVALID_TICK_SIZE` | 422 | 가격이 최소 호가 단위에 맞지 않음 |
| `SUBSCRIPTION_LIMIT_EXCEEDED` | 429 | 상품 또는 채널 구독 한도 초과 |
| `SEQUENCE_GAP` | Stream Error | 증분 데이터 누락. Snapshot 재동기화 필요 |
